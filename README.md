# BeerGoggleGames (Astro)

Static site built with Astro 5 + Tailwind, deployed to GitHub Pages with Actions.

## Develop
- npm install
- npm run dev

Notes:
- Content lives under `src/content` (MD/MDX) with Astro Content Collections validation.
- Types for `astro:content` are auto-generated on install and before dev via `astro sync`.

## Common tasks
- Dev server: `npm run dev`
- Type check: `npm run typecheck`
- Build: `npm run build`
- Preview build: `npm run preview`
- Generate content types: `npm run sync`
- Content normalize (image paths, lists, cleanup): `npm run content:normalize`
- Check deprecated paths: `npm run content:check`

VS Code users: see `.vscode/tasks.json` for ready-made tasks (Dev, Build, Sync, Content fix).

## Collections
- games: `src/content/games`
- drinks: `src/content/drinks` (unified cocktails/shots via `drinkType` + `bases`)
- posts: `src/content/posts`
- activities: `src/content/activities`

Frontmatter is validated in `src/content/config.ts` (Zod). See examples in each folder.

## URLs
- `/about`
- `/games/{slug}`
- `/drinks/{slug}`
- `/extras/{glossary|forfeits|wheel-of-fortune|activities|blog}`

## Search
Search data is generated by `src/pages/search-index.json.ts` at build time and consumed by the `/search` page. No external indexer required.

## Comments
Giscus is supported. Enable Discussions on this repo, create a category (e.g., "General"), then visit https://giscus.app/ to generate:
- data-repo-id
- data-category-id
Paste into `src/components/Comments.astro`.

## Contact form
Create a free Formspree form, then replace the action URL in `src/pages/contact.astro`:
https://formspree.io/forms

## Analytics
GA4 is integrated. To change the ID, either:
- Add PUBLIC_GA_ID as a Pages/Actions environment variable (e.g. `G-XXXXXXXXXX`), or
- Replace the default in `src/components/Analytics.astro`.

## Deployment
GitHub Actions deploy on push to `main` or `def-main` (see `.github/workflows/deploy.yml`). Pages should be set to "Build and deployment: GitHub Actions".

## Housekeeping
- Automated content normalization workflow can be run on-demand or weekly (see `.github/workflows/content-maintenance.yml`).
- Node version pinned via `.nvmrc` (20) and `engines` in `package.json`.
- Formatting via Prettier (`npm run format`).
